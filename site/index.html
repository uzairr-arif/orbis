It runs the tools you already trust

Orbis is not another scanner. It orchestrates the collectors you have, normalizes their output into one finding model, and correlates across them.

The first release ships with nmap, lynis, trivy, and gitleaks. Every collector implements the same adapter contract, so the list grows without changing the core.

One loop, six verbs

Every capability in Orbis serves one of six moments. If a feature does not fit the loop, it does not ship.

Discover

Find every asset you run

Understand

Normalize and correlate findings

Prioritize

Rank by real risk, not volume

Fix

Preview, approve, apply

Verify

Rescan and confirm the fix

Remember

Keep history, diff over time

Correlation engine

Three findings. One attack path.

Separate tools report fragments of the same problem. Orbis joins them into a single, explainable path so you fix the surface, not the symptoms.

nmap 22/tcp open ssh
lynis SSH: root login permitted
sshd_config PasswordAuthentication yes

Attack path ORB-8F42

  • Internet
  • Public IP 203.0.113.7
  • TCP/22
  • OpenSSH 9.2
  • Password authentication
  • Root account

Three findings collapsed into one path. Orbis risk: high

Same CVE. Different risk.

Raw severity treats every finding as equally urgent. Orbis weighs context, so the internet-facing database gets fixed today and the dev-only dependency gets a ticket.

risk = severity × exploitability × exposure × criticality × confidence

Every fix is previewed, approved, and reversible

Orbis never changes your machine on its own. A fix is a proposal you review, apply with one command, and can undo with another.

  • Preview first Every fix arrives as a reviewable diff. Nothing touches disk until you say so.
  • Explicit approval Destructive changes stop for a yes. Approval is per change, never global.
  • Rollback built in Each change records before and after hashes, so one command restores the prior state.
  • Verified, not assumed After a fix applies, Orbis rescans the finding and writes the result to history.
/etc/ssh/sshd_config finding ORB-8F42, preview
# Authentication:
-PermitRootLogin yes
+PermitRootLogin no
-PasswordAuthentication yes
+PasswordAuthentication no
# End of file
Rollback available Service: sshd orbis fix ORB-8F42

Operating principles

Guardrails, not autopilot

Orbis sits between your scanners and your systems. That position demands restraint, and restraint is designed in.

  • Local-first

    The first release works fully offline. Nothing leaves the machine unless you configure it.

  • Evidence-based AI

    Models explain findings and draft fixes. Evidence comes from scanners, never from the model.

  • Least privilege

    Agents and plugins run with the permissions they declare, and nothing more.

  • Human approval

    Automated remediation stops for a yes. Destructive actions are never silent.

  • No secret collection

    Passwords, keys, and source stay local by default. Any upload is explicit and scoped.
